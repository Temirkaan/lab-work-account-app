# 📋 Система учёта выполненных лабораторных работ (Lab Work Accounting System)

## 📋 О проекте
Веб-приложение для учёта выполненных лабораторных работ студентов. Система хранит список студентов, лабораторных работ, записи сдач и результаты проверки. Позволяет преподавателю добавлять работы, проверять сдачи, выставлять оценки и отправлять работы на доработку.

## 🎯 Цель разработки
Разработать учебное приложение для контроля лабораторных работ, объединяющее данные о студентах, работах и сдачах в одном месте.

## 📁 Структура репозитория
- `/templates` — HTML-шаблоны (index.html)
- `/static` — стили (styles.css)
- `app.py` — маршруты Flask
- `database.py` — функции работы с БД
- `schema.sql` — SQL-команды создания таблиц
- `lab_works.db` — файл базы данных SQLite (создаётся автоматически)
- `requirements.txt` — список библиотек
- `README.md` — основной файл с техническим заданием

## 1. АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ

### 1.1 Описание предметной области
В учебном процессе преподавателю важно видеть, кто сдал работу, какая оценка поставлена и кому нужна доработка. Без единой системы эти данные теряются или хранятся в разных файлах. Проект объединяет их в одном приложении.

**Проблемы текущей ситуации:**
- Данные о сдачах хранятся в разных файлах и теряются
- Нет единого места для просмотра статуса работ
- Сложно отследить, кому нужна доработка
- Отсутствует статистика по проверенным работам

### 1.2 Целевая аудитория
| Роль | Потребности |
|------|------------|
| **Преподаватель** | Добавлять лабораторные, проверять работы, выставлять оценки |
| **Студент** | Сдавать лабораторные работы |
| **Куратор группы** | Просматривать состояние сдач |

### 1.3 Решаемые задачи
- Автоматизация учёта сдачи лабораторных работ
- Централизованное хранение данных о студентах и работах
- Визуализация статусов сдач (сдана / проверена / на доработке)
- Фильтрация записей по статусу и группе
- Получение списка сдач через JSON API

## 4. МОДЕЛЬ ДАННЫХ

### 4.1 ER-диаграмма (описание связей)
```
┌─────────────────┐       ┌─────────────────┐       ┌─────────────────┐
│    students     │       │   submissions   │       │   lab_works     │
│   (Студенты)    │       │    (Сдачи)      │       │ (Лабораторные)  │
├─────────────────┤       ├─────────────────┤       ├─────────────────┤
│ id (PK)         │◄──────┤ student_id (FK) │       │ id (PK)         │
│ full_name       │       │ lab_work_id (FK)├──────►│ title           │
│ group_name      │       │ submitted_at    │       │ subject         │
│ created_at      │       │ score           │       │ max_score       │
│                 │       │ status          │       │ deadline        │
│                 │       │ comment         │       │                 │
└─────────────────┘       └─────────────────┘       └─────────────────┘
```

**Связи:**
- `students → submissions`: один студент может сдать много работ (один ко многим)
- `lab_works → submissions`: одну лабораторную работу могут сдать много студентов (один ко многим)

### 4.2 Описание таблиц

**Таблица: students (Студенты)**
| Поле | Тип | Описание | Ограничения |
|------|-----|----------|-------------|
| id | INTEGER | Уникальный номер студента | PRIMARY KEY, AUTO_INCREMENT |
| full_name | TEXT | ФИО студента | NOT NULL |
| group_name | TEXT | Название группы | NOT NULL |
| created_at | TEXT | Дата и время добавления | ISO формат |

**Таблица: lab_works (Лабораторные работы)**
| Поле | Тип | Описание | Ограничения |
|------|-----|----------|-------------|
| id | INTEGER | Уникальный номер работы | PRIMARY KEY, AUTO_INCREMENT |
| title | TEXT | Название работы | NOT NULL |
| subject | TEXT | Дисциплина | NOT NULL |
| max_score | INTEGER | Максимальный балл | - |
| deadline | TEXT | Срок сдачи | ГГГГ-ММ-ДД |

**Таблица: submissions (Сдачи)**
| Поле | Тип | Описание | Ограничения |
|------|-----|----------|-------------|
| id | INTEGER | Уникальный номер записи | PRIMARY KEY, AUTO_INCREMENT |
| student_id | INTEGER | Ссылка на студента | FOREIGN KEY → students(id) |
| lab_work_id | INTEGER | Ссылка на работу | FOREIGN KEY → lab_works(id) |
| submitted_at | TEXT | Дата сдачи | - |
| score | INTEGER | Оценка | NULL, если не проверено |
| status | TEXT | Статус | CHECK (submitted/checked/revision) |
| comment | TEXT | Комментарий преподавателя | - |

**Проверка:**
- Нельзя добавить студента без ФИО и группы
- Нельзя добавить работу без названия и предмета
- Статус может быть только: `submitted`, `checked`, `revision`
- Оценка может быть NULL, если работа не проверена

## 6. КЛИЕНТСКАЯ ЧАСТЬ

### 6.1 Описание клиентской части
Клиентская часть сделана в виде одной HTML-страницы. Всё размещено на главной, чтобы не надо было никуда переходить. Стили вынесены в отдельный файл, чтобы HTML не был перегружен.

### 6.2 Файлы клиентской части
| Файл | Назначение |
|------|-----------|
| `templates/index.html` | Главный (и единственный) шаблон: формы, список сдач, блок статистики |
| `static/styles.css` | Стили: карточки, кнопки, формы, цвета статусов |

### 6.3 Основные экраны и блоки

| Блок | Что делает | Кнопка |
|------|-----------|--------|
| **Статистика** | Показывает 3 числа: всего студентов, лабораторных, проверенных работ | Нет кнопок |
| **Форма добавления студента** | Поля: ФИО, группа | «Добавить студента» |
| **Форма добавления лабораторной** | Поля: название, предмет, макс. балл, дедлайн | «Создать работу» |
| **Форма фиксации сдачи** | Выпадающие списки студентов и работ, поле комментария | «Сдать работу» |
| **Фильтр** | Выпадающие списки: статус и группа | «Применить фильтр» |
| **Список сдач** | Таблица: студент, группа, работа, статус, оценка, комментарий, действия | «Проверить», «На доработку» |

### 6.4 Схема навигации
- Пользователь всегда находится на `/`
- При нажатии на любую кнопку отправляется POST или GET запрос на сервер
- Сервер обрабатывает запрос и возвращает редирект на `/` или обновлённую страницу
- Страница перезагружается с новыми данными после каждого действия

### 6.5 Работа кнопок и форм

**«Добавить студента»**
- Пользователь вводит ФИО и группу
- Нажимает кнопку
- Форма отправляет POST-запрос на `/students`
- Сервер добавляет запись в БД и редиректит обратно
- Страница обновляется, список студентов меняется

**«Создать работу»**
- Пользователь вводит название, предмет, макс. балл, дедлайн
- Нажимает кнопку
- POST-запрос на `/labs`
- Сервер добавляет лабораторную работу

**«Сдать работу»**
- Выбирает студента из выпадающего списка
- Выбирает лабораторную работу из выпадающего списка
- Пишет комментарий (необязательно)
- Нажимает кнопку
- POST-запрос на `/submissions`
- Сервер создаёт запись сдачи со статусом `submitted`

**«Проверить»**
- Рядом с каждой сдачей в списке есть эта кнопка
- При нажатии появляется поле для ввода оценки и комментария
- Пользователь вводит оценку и нажимает «Подтвердить»
- POST-запрос на `/submissions/<id>/check`
- Сервер обновляет статус на `checked` и сохраняет оценку

**«На доработку»**
- Рядом с каждой сдачей
- При нажатии отправляется POST-запрос на `/submissions/<id>/revision`
- Сервер меняет статус на `revision` (оценка не выставляется)

**Фильтр**
- Выбирает статус и/или группу
- Нажимает «Применить фильтр»
- Страница перезагружается с параметрами в URL: `/?status=checked&group=ИС-21`
- Сервер возвращает только отфильтрованные сдачи

### 6.6 Какие запросы клиент отправляет на сервер

| Действие | Метод | URL | Данные |
|----------|-------|-----|--------|
| Открыть главную | GET | `/` | `?status=...&group=...` |
| Добавить студента | POST | `/students` | `full_name`, `group_name` |
| Добавить лабораторную | POST | `/labs` | `title`, `subject`, `max_score`, `deadline` |
| Зафиксировать сдачу | POST | `/submissions` | `student_id`, `lab_work_id`, `comment` |
| Проверить работу | POST | `/submissions/1/check` | `score`, `comment` |
| Отправить на доработку | POST | `/submissions/1/revision` | (без данных, только ID в URL) |

## 7. СЕРВЕРНАЯ ЧАСТЬ

### 7.1 Описание серверной части
Сервер написан на Flask. Он обрабатывает запросы от клиента (браузера), добавляет студентов и лабораторные работы, фиксирует сдачи, проверяет работы и отправляет их на доработку. Также сервер умеет отдавать данные в JSON.

Вся логика работы с базой данных вынесена в отдельный файл `database.py`, чтобы не смешивать с маршрутами.

### 7.2 Структура серверной части
| Файл | Назначение |
|------|-----------|
| `app.py` | Все маршруты Flask: добавление студента, лабораторной, фиксация сдачи, проверка, отправка на доработку, JSON-API |
| `database.py` | Функции подключения к SQLite, создания таблиц, добавления/получения данных, обновления статусов. Демо-данные для тестирования |
| `lab_works.db` | База данных SQLite, создаётся автоматически при первом запуске |

### 7.3 Схема взаимодействия
```
[Браузер] → (HTTP-запрос) → [app.py]
                              ↓
                       вызывает функции
                              ↓
                       [database.py]
                              ↓
                       обращается к
                              ↓
                       [lab_works.db]
                              ↓
                       возвращает данные
                              ↓
                       [database.py]
                              ↓
                       передаёт в
                              ↓
                       [app.py]
                              ↓
(HTML или JSON) ← [Браузер] ← (ответ)
```

### 7.4 Основные маршруты

| Маршрут | Метод | Параметры | Что делает | Что возвращает |
|---------|-------|-----------|-----------|----------------|
| `/` | GET | `status`, `group` | Показывает главную страницу со списком студентов, работ и сдач. Считает статистику | HTML-страница |
| `/students` | POST | `full_name`, `group_name` | Добавляет нового студента | Redirect на `/` |
| `/labs` | POST | `title`, `subject`, `max_score`, `deadline` | Добавляет новую лабораторную работу | Redirect на `/` |
| `/submissions` | POST | `student_id`, `lab_work_id`, `comment` | Фиксирует сдачу (статус `submitted`) | Redirect на `/` |
| `/submissions/<id>/check` | POST | `score`, `comment` | Проверяет работу: выставляет оценку, статус `checked` | Redirect на `/` |

| `/api/submissions` | GET | `status`, `group` | Возвращает список сдач в JSON | JSON |

## 8. БАЗА ДАННЫХ

### 8.1 Краткое описание
Для хранения данных выбран SQLite, потому что он не требует установки отдельного сервера, всё хранится в одном файле `lab_works.db`. Это удобно для учебного проекта — можно скопировать базу вместе с кодом, и всё сразу заработает.

В базе три таблицы:
- `students` — список студентов
- `lab_works` — список лабораторных работ
- `submissions` — записи о том, кто, когда и какую работу сдал, с оценкой и статусом

Таблицы связаны через внешние ключи: одна запись в `submissions` ссылается на одного студента и одну лабораторную работу.

### 8.2 Где находится база данных в проекте
| Файл | Назначение |
|------|-----------|
| `lab_works.db` | Файл базы данных SQLite. Создаётся автоматически при первом запуске |
| `schema.sql` | SQL-команды для создания таблиц |
| `database.py` | Все функции, выполняющие запросы к базе |

Файл базы лежит в корне проекта, не в папке `templates` или `static`.

### 8.3 Примеры SQL-запросов

**Пример 1: Получить всех студентов**
```sql
SELECT * FROM students;
```

**Пример 2: Получить все непроверенные сдачи**
```sql
SELECT * FROM submissions WHERE status = 'submitted';
```

**Пример 3: Получить список сдач с именами студентов и названиями работ**
```sql
SELECT students.full_name,
       students.group_name,
       lab_works.title,
       submissions.score,
       submissions.status
FROM submissions
JOIN students ON students.id = submissions.student_id
JOIN lab_works ON lab_works.id = submissions.lab_work_id;
```

**Пример 4: Добавить нового студента**
```sql
INSERT INTO students (full_name, group_name, created_at)
VALUES ('Сидорова Анна', 'ИС-21', '2026-04-29 10:30:00');
```

**Пример 5: Обновить статус и оценку (проверка работы)**
```sql
UPDATE submissions
SET score = 8, status = 'checked', comment = 'Хорошо, но есть недочёты'
WHERE id = 5;
```

**Пример 6: Отправить на доработку**
```sql
UPDATE submissions
SET status = 'revision', comment = 'Переделать вывод'
WHERE id = 7;
```

**Пример 7: Получить статистику (сколько проверенных работ)**
```sql
SELECT COUNT(*) FROM submissions WHERE status = 'checked';
```

### 8.4 Демо-данные
При первом запуске `database.py` создаёт таблицы и добавляет немного демо-данных, чтобы было с чем работать.

## 11. ВЫВОД

Клиентская часть сделана на одной HTML-странице с формами и таблицей. Все кнопки и формы работают, отправляют данные на сервер и получают обратно обновлённую страницу. Стили вынесены в отдельный файл. Навигации как таковой нет, потому что всё на одной странице — это просто для преподавателя, ему не нужно искать, где что находится.

Серверная часть написана на Flask. Маршруты в `app.py`, функции для работы с базой данных — в `database.py`. Сервер умеет добавлять студентов, лабораторные работы, фиксировать сдачи, проверять их и отдавать JSON.

База данных сделана на SQLite, три таблицы связаны через внешние ключи. Схема описана в `schema.sql`, все запросы вынесены в `database.py`, чтобы серверная часть (`app.py`) не работала напрямую с SQL. Данные хранятся нормализованно (без лишних повторений). Демо-данные добавлены для тестирования.

Всё работает локально, интерфейс понятный. В следующих заданиях можно будет добавить, например, подтверждение перед отправкой на доработку или всплывающие уведомления.
